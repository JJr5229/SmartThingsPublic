# Etsy Listing Copy for Digital Planner Apps

If this shop has an existing `etsy-listing-copy` skill for physical products, use its *structural*
discipline (title rules, tag rules, description section order) but swap every physical-product
section for a digital-product equivalent. Don't force PLA/material/care boilerplate or
size-and-quantity/stacking language onto a software product — it reads as an obvious copy-paste
error to a buyer and undermines trust.

## Title

Same rules as physical listings: front-load the primary keyword phrase in the first ~40 characters
(mobile search results truncate there), stay under 140 characters total, write it as natural
readable phrases separated by pipes rather than a keyword pile, no promotional language ("best
seller," "limited time"), no medical/therapeutic claims.

Structure: `[Niche + "Planner Template"] | [2-3 standout feature nouns] | [format/delivery hook]`

Example shape (wedding): `Digital Wedding Planner Template | Budget Tracker, Guest List, Seating
Chart & Checklist | Editable Web App, Instant Download`

## Description sections, in order

1. **Header** — the title repeated plain/bold at the top.
2. **Opening hook** (2-3 sentences) — the single strongest benefit stated as natural sentences, not
   a keyword list. The first ~160 characters show in search snippets, so the best line goes first.
3. **Feature/function paragraph(s)** — what it does, in the order that best tells "not just a
   spreadsheet."
4. **"Perfect for" paragraph** — who buys this and why (the target buyer inferred in Phase 0).
5. **✔ bullet list** — one feature per line, punchy restatement of section 3.
6. **What's Included** *(replaces physical "Size & Quantity")* — state explicitly this is one (1)
   digital file (format), delivered as an instant download, opens in any modern browser on desktop
   or mobile, no installation/account/subscription, single-user personal-use license (or whatever
   the actual license terms are — flag if unspecified).
7. **Color/Theme Options** — list the actual palette names built in Phase 0. Unlike a physical
   product's made-to-order color, this is a real always-available feature — name it explicitly and
   describe switching between them in the app itself as one click.
8. **How It Works** *(replaces physical "Material")* — no sign-up/login/subscription, runs entirely
   in the browser, data saves locally on the buyer's device (never uploaded anywhere — a genuine,
   provable claim if the app truly has no backend), Save/Restore backup-file workflow explained in
   plain language.
9. **Suggested Uses** — short list of search-style use cases; doubles as a source for tag ideas.
10. **Format** *(replaces physical "Care Instructions")* — reiterate: digital file, not physical,
    self-contained web page, no ongoing internet connection required after download, no recurring
    fees.
11. **Good to Know / FAQ** — 2-4 short Q&As preempting real objections: account/subscription
    question, where does my data go, what if I switch devices, can I use this on my phone.
12. **Please Note** *(replaces physical "Please Note" but digital-flavored)* — no physical item
    ships, ensure buyer has a modern browser before purchasing, standard digital-goods
    non-refundable-after-download language (confirm actual policy with the user rather than
    assuming), screenshots show placeholder sample data.

## Tags (exactly 13, each ≤20 characters)

Same discipline as physical listings: multi-word phrases (not single words), no repeated root words
wasting slots, no color-specific tags (color/theme here is a feature of every purchase, not a
made-to-order variant worth a dedicated tag), no trademarked terms.

Aim for this mix: 3-4 core function phrases (`[niche] planner`, `budget tracker`, a niche-specific
module name), 2-3 use-case phrases, 2 gift/occasion phrases, 2 style/format phrases
(`editable template`, `instant download`), 1-2 audience phrases, 1-2 differentiator phrases
(`paperless [niche]`, `offline [niche] tool`).

## Compliance pass

Before presenting final copy, scan for: ALL CAPS, promotional language, trademarked brand names,
"inspired by" phrasing, medical/therapeutic claims. Strip or rewrite anything that violates these —
same bar as the shop's physical listings.

## Flag assumptions

Always call out anything filled in with a reasonable default rather than confirmed fact — license
terms, refund policy specifics, exact price — so the user can correct it before publishing rather
than discovering it's wrong after the listing is live.
